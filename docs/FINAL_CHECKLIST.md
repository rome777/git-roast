## 2. 비정상 입력 및 예외 흐름 방어 검증 (Edge Cases & Error Handling)

사용자가 개발자가 의도하지 않은 방식으로 조작하거나 비정상적인 값을 넣더라도 시스템이 크래시되지 않고 우아하게 대응(Graceful Degradation)하는지 검증합니다.

- [ ] **GitHub 입력 예외 처리**:
  - [ ] **존재하지 않는 GitHub 사용자명**을 입력했을 때: "해당 GitHub 사용자를 찾을 수 없습니다. 아이디를 다시 확인해 주세요." 친절한 에러 토스트 표시.
  - [ ] **특수문자/공백/빈 값** 입력 시: 클라이언트 측 유효성 검사에서 즉각 차단.
  - [ ] **활동이 전무한 계정** (잔디 0개, 리포 0개): "분석할 활동 내역이 없습니다." 전용 빈 상태(Empty State) UI 표시.
  - [ ] **GitHub API Rate Limit 초과 시**: 시스템 에러를 내뿜지 않고 Mock Fallback 안내 및 대기 시간 안내 제공.
- [ ] **인증 및 폼 입력 예외 처리**:
  - [ ] **비밀번호 없이** 로그인/가입 시도 시: 폼 제출을 막고 에러 메시지 표시.
  - [ ] **가입되지 않은 이메일**로 로그인 시도 시: 정확한 오류 안내 (보안상 "이메일 또는 비밀번호가 일치하지 않습니다"로 모호화).
  - [ ] **비밀번호 최소 길이 미달(8자 미만)** 시도 시 실시간 가이드 표시.
  - [ ] **이미 가입된 이메일**로 중복 가입 시도 시 적절한 경고 표시.
- [ ] **비인가 라우트 직접 접근 방어**:
  - [ ] 로그인하지 않은 상태에서 즐겨찾기 해둔 `/dashboard` 또는 `/analyze` URL로 직접 타이핑 접속 시 $\rightarrow$ 즉시 `/login`으로 리다이렉트되며 원래 가려던 목적지(`?redirect=/dashboard`) 기억.
  - [ ] 로그인 세션이 만료된 상태에서 분석 버튼 클릭 시 세션 만료 팝업 및 로그인 유도.
  - [ ] 타인의 비공개(private) 평가 상세 URL(`/result/[id]`)에 직접 접근 시 404 또는 접근 거부 페이지 렌더링.

## 3. 보안 심층 체크리스트 (Security Deep Dive - 8대 핵심 수칙)

> **⚠️ 아키텍처 변경 반영 (2026-09-08)**
> 본 절은 원래 **Supabase Auth + RLS** 를 전제로 작성되었으나, 실제 구현은
> **자체 세션 체계(HMAC 서명 쿠키 + scrypt 비밀번호 + 서버측 권한 게이트)** 로 완성되었다.
> Supabase 연동 코드(`lib/supabase/*`)는 환경 변수 미설정으로 현재 비활성 상태다.
> 따라서 Supabase 종속 항목은 **N/A** 로 표기하고, 자체 체계에 해당하는 항목으로 대체 검증했다.
> 검증 방식: 실행 중인 서버(`localhost:3000`)에 실제 HTTP 요청을 보내 응답 코드를 확인. **31건 전부 통과.**

- [x] **1. 키·토큰 격리 및 유출 방지**:
  - [x] `NEXT_PUBLIC_` 접두사가 붙은 환경변수에 `SERVICE_ROLE_KEY`, `GEMINI_API_KEY`, `GITHUB_TOKEN`이 포함되어 있지 않은가?
  - [x] 브라우저 개발자 도구(F12) Network 탭과 번들 JS 파일에서 시크릿 키가 검색되지 않는가?
        → 서버 전용 코드에서만 참조. 데모 계정 비밀번호도 서버에서 생성해 클라이언트로 나가지 않음.
  - [x] `.gitignore`에 `.env`, `.env.local`이 등록되어 소스 코드 저장소에 키가 커밋되지 않는가?
        → `.gitignore` 신설. `data/*.db`(개인 분석 기록)도 함께 제외.
  - [ ] **미결**: 과거 `HANDOVER.md` 에 평문 노출되었던 Gemini/Vertex 키 **폐기 및 재발급** (사용자 조치 필요)
- [ ] **2. 이메일 확인 및 무제한 가입 방어**:
  - [ ] ~~Supabase Auth `Enable Email Confirmations`~~ → **N/A** (Supabase Auth 미사용)
  - [x] 이메일 형식 검증으로 명백한 허위 입력 차단 (`notanemail` → 400), 중복 가입 차단 (409)
  - [ ] **미구현**: 실제 메일 발송 기반 소유 확인. 현재는 형식 검증까지만.
- [x] **3. 비밀번호 정책**:
  - [x] 8자 미만 비밀번호 거부 (로그인·가입 모두 400)
  - [x] 평문 저장 없음 — scrypt(salt 16B, key 64B) 해시, 비교는 `timingSafeEqual`
  - [x] 계정 존재 여부 미노출 — 없는 계정/틀린 비밀번호 모두 동일 문구 + 401
  - [ ] ~~HaveIBeenPwned 연동~~ → **미구현** (선택 항목)
- [ ] **4. 남용 및 디도스(DDoS) 방어**:
  - [ ] **미구현**: Rate Limit (429). 비로그인 사용자도 분석 가능해 Gemini 호출 비용이 열려 있음. **운영 전 최우선 과제.**
  - [x] 프롬프트 인젝션 내성: `responseMimeType: "application/json"` 강제 + 3중 파싱 방어.
        파싱 실패 시 예외를 삼키지 않고 다음 모델로 전환하도록 보강.
- [x] **5. 행 수준 접근 제어 (자체 구현으로 대체)**:
  - [ ] ~~Supabase RLS 활성화~~ → **N/A** (SQLite/PostgreSQL 직접 접근)
  - [x] 모든 조회·삭제 쿼리가 **세션 이메일로 스코프**됨 (`WHERE user_email = ?`). 요청 본문·쿼리스트링의 `email`/`userId` 는 소유자 판정에 쓰지 않음.
  - [x] 타 사용자 ID 위조 요청 거부 검증:
        평문 레거시 쿠키 / 서명 없는 토큰 / 서명 위조 토큰 / `?email=` 우회 → **4종 전부 401**
  - [x] 일반 사용자 세션으로 관리자 API 조회·삭제 시도 → **전부 403**
  - [x] 관리자 권한은 토큰의 `role` 이 아니라 **매 요청 DB 재조회**로 판정 (권한 회수 즉시 반영)
- [ ] **6. 도메인 및 리다이렉트 화이트리스트**:

  - [x] 로그인·로그아웃 리다이렉트가 모두 앱 내부 고정 경로(`/dashboard`, `/`)로만 이동 — Open Redirect 경로 없음
- [x] **7. 데이터 최소 수집 및 로깅**:
  - [x] 비밀번호 평문을 로그에 남기지 않음 (해시만 저장, 검증 결과만 로깅)
  - [x] 공유 링크 공개 API(`/api/evaluations/[id]`)가 **소유자 이메일을 응답에 포함하지 않음** (검증 완료)
